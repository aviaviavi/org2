* Org2
#+attr_html: :width 100px
[[./logo.png]]

A from-scratch successor to Org Mode, built to be editor-agnostic and platform-agnostic.

Reference: https://avi.press/posts/2024-01-15-standalone-org.html

** Status

Org2 is *early alpha*.

- Goal: drop-in replacement for most Org Mode users in Emacs, plus a full Org-style experience for non-Emacs users
- Best-supported workflow today: VS Code + CLI (already practical for daily notes/tasks)
- Core language support is broadly implemented
- 100% feature-for-feature GNU Org parity is *not* the project goal
- APIs and command flags may still change

** What’s working now

- Core Org structures: headings, drawers/properties, links, planning lines, TODO states
- Agenda workflows (CLI + VS Code)
- Basic editing workflows (TODO/planning updates, archive/refile, capture)
- HTML export (MVP)
- LSP server (MVP) for links/navigation/completions/formatting

** What’s not done yet

- Full Org Mode parity
- Mature recurring/habits/clocking ecosystem
- Stable plugin ecosystem
- Broad editor parity beyond VS Code

** Docs site

The repo includes a basic docs site authored in Org files under =docs/site/=.

Generate it locally:

#+begin_src sh
npm run org2 -- publish docs-site --config org2.json
#+end_src

Output is written to =site/=. On GitHub, =.github/workflows/docs-pages.yml= builds and deploys this to GitHub Pages.

** Quick start

#+begin_src sh
cd /path/to/org2
npm install
npm run build
#+end_src

Run CLI from source:

- =npm run org2 -- <command> [...args]= (recommended)
- =node dist/cli.js <command> [...args]=

Discover current commands/flags:

#+begin_src sh
npm run org2 -- --help
npm run org2 -- agenda --help
#+end_src

** Common CLI usage

Agenda on a directory:

#+begin_src sh
npm run org2 -- agenda --dir /path/to/org --recursive
npm run org2 -- agenda --dir /path/to/org --recursive --tui
#+end_src

The TUI groups overdue, today, and the next 7 days into collapsible left-pane sections. Use =j/k= or arrow keys to move, =gg= / =G= to jump to the top or bottom, =h=/left to collapse the current section, =l=/right to expand it, =Enter= or =Space= to toggle the wrapped detail pane, =x= to toggle TODO/DONE, =r= to refresh, and =q= to quit.

Agenda on explicit files:

#+begin_src sh
npm run org2 -- agenda --files a.org b.org
#+end_src

Bounded range + JSON:

#+begin_src sh
npm run org2 -- agenda --from 2026-01-01 --to 2026-01-31 --format json
#+end_src

Run language server:

#+begin_src sh
npm run org2 -- lsp
#+end_src

Org-crypt basics (decrypt/encrypt subtree at cursor line):

#+begin_src sh
npm run org2 -- crypt decrypt --file notes.org2 --line 42 --passphrase 'your-passphrase' --apply
npm run org2 -- crypt encrypt --file notes.org2 --line 42 --passphrase 'your-passphrase' --apply
#+end_src

** Release packaging

Tag-based releases publish both packages:

- npm package (=@aviaviavi/org2=)
- VS Code extension (=editors/vscode-org2=)

Workflow: =.github/workflows/release-packages.yml=

Trigger:
- push a SemVer tag like =v0.1.0=

Required GitHub secrets:
- =VSCE_PAT=
- =OVSX_PAT= (optional; publishes to Open VSX when provided)

npm publishing uses Trusted Publishing (OIDC), so no long-lived =NPM_TOKEN= secret is required.

The release workflow also uploads built artifacts (=*.tgz= and =*.vsix=) to the GitHub Release.
