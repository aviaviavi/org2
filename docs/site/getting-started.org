The current end-to-end agent setup uses *OpenClaw*. The native lifecycle plugin feeds substantial OpenClaw work into Agent Work, and the Mac chat connects directly to an OpenClaw Gateway. This reflects the first adapter that has been implemented, while the underlying CLI, run files, workflows, context interfaces, and MCP surface remain available to Codex, local models, scripts, and future agent integrations.

* 1) Install Org2

** CLI

For normal command-line use, install the published package:

#+begin_src sh
npm install -g @aviaviavi/org2
org2 --help
org2 agenda --help
org2 agent capabilities
#+end_src

You can also try it without a global install:

#+begin_src sh
npx @aviaviavi/org2 --help
#+end_src

For source builds and contribution work, use the repository:

#+begin_src sh
git clone https://github.com/aviaviavi/org2.git
cd org2
npm ci
npm run build
#+end_src

Sanity check the source-built CLI:

#+begin_src sh
npm run org2 -- --help
npm run org2 -- agenda --help
#+end_src

The examples below use =org2=. If you are running from a checkout instead of a global install, replace =org2= with =npm run org2 --=.

** macOS app

Org2 Workspace is the native macOS app. The easiest install path is the downloadable disk image from GitHub Releases:

1. Download the latest =Org2Workspace.dmg= from [[https://github.com/aviaviavi/org2/releases][GitHub Releases]].
2. Open the disk image and drag =Org2Workspace.app= into =Applications=.
3. Open the app from =Applications= and choose the folder that contains your Org2 or Org corpus.

On first launch, the Workspace offers two paths:

- *Open an existing corpus* to point Org2 at any folder of =.org= or =.org2= files. No migration is required.
- *Create a new corpus* to choose an empty folder and add a small starter layout: =org2.json=, an optional transport inbox, a welcome note, =daily/=, =notes/=, =views/=, =compiled/=, and =workflows/=. Mac quick capture appends to today's daily note; a sync-constrained client may use the inbox as an isolated intake buffer.

The starter is ordinary plain text and directories, not an app-owned database. You can immediately inspect or edit every generated file in Finder, Git, or another editor.

To publish a talk, open an =.org= or =.org2= file and choose *File → Export Slides as PDF…* or *Export Slides as LaTeX…*. The PDF path uses the shared Beamer compiler and requires a TeX installation such as MacTeX. See [[file:editors-macos.org][macOS Workspace → Slide export]] for slide structure, compatibility, and troubleshooting.

For a team pilot, create or identify a separate shared corpus rather than exposing a personal corpus. The Mac app remembers multiple mounts and keeps writes scoped to the active corpus. See [[file:collaboration.org][Shared corpora and collaboration]].

The initial downloadable disk image is built for Apple Silicon Macs. Current release builds are developer-signed, not notarized. If macOS blocks the first launch, open *System Settings → Privacy & Security* and allow Org2Workspace, or right-click the app in Finder and choose *Open*.

For source builds and local dogfooding, build the app from the repository:

#+begin_src sh
npm ci
npm run build
npm run build:macos-app
open ~/Applications/Org2Workspace.app
#+end_src

See [[file:editors-macos.org][macOS Workspace]] for the current app surface.

** Current agent setup: OpenClaw

There are two complementary OpenClaw connections:

1. The =org2-lifecycle= plugin records substantial main-agent turns, subagent executions, and cron executions as durable Org2 runs. Stable OpenClaw keys correlate retries and lifecycle events without turning ordinary conversation or personal TODOs into runs.
2. The Mac app's *AI Chat* surface supports per-thread OpenClaw or local Codex. OpenClaw connects to the Gateway for selected-agent chat, streamed progress, tool activity, runtime slash commands, and stop control.

From an Org2 checkout, install and inspect the lifecycle plugin with:

#+begin_src sh
npm run test:openclaw
openclaw plugins install --link ./integrations/openclaw
openclaw plugins inspect org2-lifecycle --runtime --json
#+end_src

In OpenClaw configuration, explicitly enable =org2-lifecycle=, allow its typed conversation hooks, and set =corpusDir= to the Org2 corpus you want represented in Agent Work. Restart the Gateway after installing or changing plugin code. The plugin's [[https://github.com/aviaviavi/org2/tree/main/integrations/openclaw][integration README]] carries the source-local setup notes.

To connect an OpenClaw thread, open *AI Chat → Configure*, enter the Gateway endpoint and token, select the agent, and save. A remote Gateway normally requires device pairing: use *Save & Request Pairing*, approve the displayed request on the Gateway host, and reconnect. The app can use the OpenAI-compatible endpoint as a reduced-observability fallback for ordinary chat, while Gateway-native commands and lifecycle features require the live protocol.

** iOS app

Org2 Mobile is currently distributed as source, not through the App Store or TestFlight.

To install it on a simulator or your own device:

1. Open =apps/ios/Org2Mobile/Org2Mobile.xcodeproj= in Xcode.
2. Select the =Org2Mobile= app target and choose your Apple development team.
3. For device builds, enable the =group.org.org2.mobile= App Group for both the app and share extension in the Apple developer portal.
4. Build and run from Xcode.
5. In the app, select an iOS Files-visible corpus folder, usually one synced with Syncthing-compatible tooling such as Möbius Sync.

See =apps/ios/Org2Mobile/README.md= for the current sync shape and share-extension notes.

Org2 Mobile can also control Mac-hosted AI chats without syncing the chat runtime to the phone. Install Tailscale on both devices, then open *Org2 Workspace → Settings… → Mobile Remote* on the Mac, enable the listener on its detected =100.x.y.z= address, create a one-time code, and scan it from the iOS *Remote* tab. The Mac stays responsible for model access and corpus context and must remain awake with Org2 Workspace running.

* 2) Start with your existing Org files as compiler input

You do *not* need to convert everything first.

Org2 is designed to work with existing =.org= files right away.

Example:

#+begin_src sh
org2 agenda --dir /path/to/your/notes --recursive
#+end_src

For a keyboard-driven planning view, add the agenda TUI:

#+begin_src sh
org2 agenda --dir /path/to/your/notes --recursive --tui
#+end_src

That means you can start by pointing Org2 at your current notes directory and treating it as input to the compiler pipeline: raw files → structured notes → compiled semantics → views and published outputs. Adopt =.org2= for new files when you want to.

* 3) Use VS Code if you want the best editor experience today

VS Code is currently the strongest Org2 editor target.

High-value workflows already available there:

- agenda UI
- TODO / planning edits
- capture / archive / refile
- formatter preview + apply flows
- roam backlinks / IDs / dailies
- HTML export
- shared navigation and editing features

See [[file:editors-vscode.org][VS Code]] for the current command/keybinding surface.

* 4) Prefer =.org2= for new files

For new files, using =.org2= is a good default.

Why:

- clearer intent,
- easier editor/tool targeting,
- cleaner long-term migration path.

But =.org= remains a first-class input format for current workflows.

* 5) Learn the core CLI workflows

The most useful commands to know first are:

- =agenda=: inspect scheduled/deadline items across files; add =--tui= for the interactive terminal agenda
- =todo= / =plan=: edit task state and planning metadata
- =capture=: append quick entries
- =archive= / =refile=: reorganize trees
- =fmt=: canonical formatting
- =roam ...= / =id= / =query= / =backlinks=: linked-note workflows
- =agent capabilities= / =agent context= / =context= / =brief=: discover functionality and retrieve cited, bounded context for agents
- =query-data= / =render-chart=: materialize explicit datasets/SQL and render deterministic charts
- =export html= / =publish=: produce docs and sites
- =export beamer=: produce Beamer LaTeX or compile a presentation PDF
- =lsp=: optional shared editor backend for clients that use the protocol

* 6) Generate the docs site locally

The repository includes a docs site authored in Org files under =docs/site/= and published with Org2 itself.

#+begin_src sh
org2 publish docs-site --config org2.json
#+end_src

* 7) What to expect right now

** Strong today

- core Org language support
- practical planning workflows
- strong VS Code support
- roam-style linked-note workflows
- HTML export + publish pipeline
- Beamer-compatible presentation export to TeX/PDF
- useful editor backend support
- cited agent retrieval and a machine-readable installed capability manifest
- local/remote data notebooks with explicit refresh and chart rendering
- OpenClaw lifecycle capture into durable runs plus native Gateway chat in the Mac app

** Still evolving

- final CLI/API stability
- broader editor parity beyond VS Code
- full long-tail Org ecosystem depth (habits, clocking, etc.)
