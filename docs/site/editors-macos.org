#+TITLE: macOS Workspace

Org2 Workspace is the native macOS client for working with an Org2 corpus. It is an alpha app in =apps/macos/Org2Workspace=, built as a Swift Package, and uses the same parser/CLI output as the rest of Org2 instead of maintaining a private database.

The app is currently best understood as a local workspace shell for dogfooding the product direction: agenda review, file navigation, search, rendered block editing, meeting capture, OpenClaw handoff, workstream kickoff, and crypt workflows over normal files.

* Current surfaces

The sidebar exposes the main workspace surfaces:

- *Agenda* :: review scheduled/deadline work across the selected corpus, filter items, switch agenda modes, mutate TODO/planning state, and open the selected item in the detail pane.
- *Files* :: scan =.org2=, =.org=, and Markdown files, filter them, and quick-open a file with keyboard shortcuts.
- *Search* :: run corpus search through the shared Org2 tooling and open results with source context.
- *Meetings* :: record or import local audio, create meeting/transcript artifacts under the corpus, and keep transcription provenance in Org2 files.
- *OpenClaw Chat* :: send selected workspace context to a configured OpenClaw endpoint while keeping the conversation state local to the app.
- *Agent Space* :: browse durable OpenClaw/agent thread records and reopen their source context.
- *Workstreams* :: track the parallel app slices, start autonomous loop artifacts, create knowledge nodes, and run first-run health checks for repo/build/corpus readiness.

The detail pane can render a selected file, agenda item, search result, backlink, meeting note, or agent thread. It supports both raw source editing and structured rendered-block editing.

* Document editing

The rendered editor is meant to make Org-shaped text feel native without hiding the source file. Current editing affordances include:

- heading, planning, keyword, property drawer, paragraph, list item, media, quote, source, and table block editors,
- block selection, insertion, duplication, deletion, movement, and folding,
- inline editing for links, timestamps, and markup,
- TODO, priority, tag, planning, property, and checkbox quick edits,
- source block execution for supported local languages,
- syntax-highlighted raw text editing with autosave-oriented block updates.

The important product rule is that the app should write ordinary Org2 text. Users should be able to inspect every change in Git or another editor.

* Meetings

Org2 Workspace records meetings as local corpus artifacts. A meeting write normally creates an audio file, a meeting note, and a transcript artifact under =meetings/=.

Transcription is local-first. The app tries a configured =ORG2_WORKSPACE_WHISPER_COMMAND=, then common whisper.cpp commands, then the OpenAI Whisper CLI. If no local transcriber is available, it still writes the meeting artifacts with =:transcription_status: unavailable= rather than uploading private audio.

See [[https://github.com/aviaviavi/org2/blob/main/docs/meetings.md][Org2 meetings]] for the artifact shape and transcriber resolution order.

* OpenClaw and agents

The app includes two OpenClaw-oriented surfaces:

- a chat panel/full-page chat for sending messages with current workspace context,
- an Agent Space browser for durable agent-thread records in the corpus.

This is deliberately a handoff boundary. The corpus stores selected context, thread references, transcript references, and durable outputs; the external agent can act on that context without the Mac app becoming the only source of truth.

* Org-crypt

The app includes configuration and run actions for GPG-backed =:crypt:= subtrees. It can encrypt plaintext =:crypt:= subtrees on save, decrypt selected encrypted subtrees for review, manage recipient lists, and use the macOS keychain for the optional passphrase workflow.

* Parallel workstreams

The Workstreams surface is the kickoff point for building several major slices in parallel without losing the shared product shape. It is oriented around creating durable corpus artifacts, not adding manual queues that only the Mac app understands:

- *Autonomous Capture* starts a capture loop under =loops/= that records its workstream, loop status, creation timestamp, and next actions in ordinary Org2 text.
- *Meeting to Action* starts a meeting action loop for the selected meeting artifact, carrying the meeting file, transcript reference, and durable follow-up prompts into the corpus.
- *Knowledge Browser* opens ID/backlink context when a selected node already has an ID, and otherwise helps create a new ID-backed knowledge node in the configured roam/index directory.
- *Packaging and First Run* runs local health checks for repo discovery, built CLI/parser files, Node dependencies, Swift package presence, corpus writability, corpus config, and loop-directory readiness.

The loop artifacts are intentionally plain files. External agents, scripts, Git review, and other editors can inspect or continue the same work without relying on private app state.

* Keyboard model

The app has global navigation shortcuts for major surfaces and local keyboard loops for agenda/document work.

High-value shortcuts include:

- =Cmd-1= through =Cmd-5= for primary surfaces,
- =Cmd-6= for Agent Space,
- =Cmd-Shift-7= for Workstreams,
- =Cmd-P= / =Cmd-K= for quick open,
- =Cmd-7=, =Cmd-8=, and =Cmd-9= for today/yesterday/tomorrow daily notes,
- agenda-local =j= / =k= navigation, =/= filtering, and TODO/planning shortcuts,
- document-local block navigation, editing, insertion, folding, duplication, movement, and deletion shortcuts.

Use the in-app keyboard shortcuts sheet for the full current map.

* Build and run

From the repository root:

#+begin_src sh
npm install
npm run build
cd apps/macos/Org2Workspace
swift run Org2Workspace
#+end_src

The app expects =dist/cli.js= and =dist/parse.js= to exist. If the app cannot find the repo root automatically, set =ORG2_REPO_ROOT= before launching:

#+begin_src sh
ORG2_REPO_ROOT=/path/to/org2 swift run Org2Workspace
#+end_src

* Next major slices

The recommended lead slice remains *autonomous capture and knowledge loops*.

The goal is to make the Mac app good at creating the right durable work context with as little human shepherding as possible:

- one-click creation of capture loops, meeting loops, and knowledge nodes,
- loop artifacts that agents can pick up without scraping app UI state,
- source-linked meeting promotion into decisions, TODOs, and durable notes,
- ID/backlink-first knowledge creation rather than private graph state,
- acceptance paths where generated tasks, notes, and loop status remain clean =.org2= text.

That slice should stay first because it closes the core loop from signal to durable knowledge. Meeting promotion, knowledge browsing, and packaging can proceed in parallel as long as they preserve shared write semantics: meeting promotion should create ordinary TODOs/notes, the knowledge browser should reuse IDs/backlinks rather than private graph state, and packaging should verify the same CLI/parser artifacts the app actually calls.
