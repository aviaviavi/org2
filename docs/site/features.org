    <p class="org2-kicker">One corpus. Many useful surfaces.</p>
    <h2 id="feature-hero-title">Plain text in. A working knowledge system out.</h2>
    <p>Org2 is a local-first context compiler for notes, tasks, meetings, data, and agent work. Keep ordinary files as the source of truth; derive agendas, graphs, cited context, review queues, editor intelligence, and published artifacts from one shared semantic model.</p>

  <section class="org2-feature-section" id="compiler-loop" aria-labelledby="compiler-loop-title">
    <div class="org2-feature-heading">
      <p class="org2-kicker">The compiler loop</p>
      <h2 id="compiler-loop-title">Capture once. Compile many views.</h2>
      <p>Org2 does not make each client rediscover what your files mean. The shared parser resolves structure and relationships once, then every surface consumes the same semantics.</p>
    </div>
    <div class="org2-compiler-flow" aria-label="Org2 compiler workflow">
      <article><span>01</span><strong>Capture</strong><p>Notes, TODOs, meetings, links, files, data records, and agent handoffs stay in inspectable text.</p></article>
      <article><span>02</span><strong>Parse</strong><p>Headings, properties, timestamps, blocks, tables, source ranges, and artifact metadata become structure.</p></article>
      <article><span>03</span><strong>Resolve</strong><p>IDs, backlinks, planning state, provenance, graph edges, approvals, and freshness become shared semantics.</p></article>
      <article><span>04</span><strong>Derive</strong><p>Agendas, diagnostics, graphs, context packs, apps, editor features, reports, and sites fall out of the model.</p></article>
    </div>
    <p class="org2-feature-note"><strong>The important boundary:</strong> the Mac app, VS Code, CLI, agents, and publishing pipeline are clients of the corpus—not competing databases.</p>
  </section>

  <section class="org2-feature-story" id="planning-knowledge" aria-labelledby="planning-knowledge-title">
    <div class="org2-feature-copy">
      <p class="org2-kicker">Planning + knowledge</p>
      <h2 id="planning-knowledge-title">Plan from the same files you think in.</h2>
      <p>TODO state, schedules, deadlines, priorities, effort, tags, IDs, aliases, and links remain readable in the note. Org2 turns them into focused agenda views and a navigable knowledge graph.</p>
      <ul>
        <li>Agenda across many files, with date windows, filters, grouping, and real-world TODO vocabularies.</li>
        <li>Stable IDs, backlinks, dailies, node creation, link previews, and graph-health checks.</li>
        <li>Preview-first mutations from the CLI and editors; writes require an explicit apply step.</li>
      </ul>
      <div class="org2-command" aria-label="Planning and graph commands">
        <span>Try the shared model from the terminal</span>
        <pre><code>org2 agenda --dir ~/notes --recursive --tui
org2 roam graph --dir ~/notes --recursive --format report</code></pre>
      </div>
      <p class="org2-feature-links"><a href="workflows.html">Explore everyday workflows</a> <a href="tooling-reference.html">See CLI reference</a></p>

  <section class="org2-feature-story org2-feature-story-reverse" id="agent-work" aria-labelledby="agent-work-title">
    <div class="org2-feature-copy">
      <p class="org2-kicker">Agent collaboration</p>
      <h2 id="agent-work-title">Give agents context without giving up the paper trail.</h2>
      <p>Selected context, citations, plans, budgets, outputs, validation, clarifications, and approvals live in durable run and workflow records. People can inspect what happened before approving a consequential action.</p>
      <ul>
        <li>Bounded context packs carry file-and-line citations instead of an opaque prompt dump.</li>
        <li>Generated work lands in reviewable artifact zones before promotion into canonical notes.</li>
        <li>OpenClaw is the first native end-to-end integration; CLI, MCP, and plain files keep the model provider-independent.</li>
      </ul>
      <div class="org2-command" aria-label="Agent context and review commands">
        <span>Retrieve cited context, then inspect pending decisions</span>
        <pre><code>org2 agent context --query "launch risks" --dir ~/notes --recursive
org2 review list --status pending --dir ~/notes</code></pre>
      </div>
      <p class="org2-feature-links"><a href="agent-quickstart.html">Agent quickstart</a> <a href="openclaw-knowledge-layer.html">OpenClaw integration</a></p>

  <section class="org2-feature-story" id="data-notebooks" aria-labelledby="data-notebooks-title">
    <div class="org2-feature-copy">
      <p class="org2-kicker">Data notebooks</p>
      <h2 id="data-notebooks-title">Put the evidence beside the decision.</h2>
      <p>Org2 notes can declare local or configured remote datasets, reusable SQL views, materialized results, freshness policy, and deterministic charts. Refresh is explicit; merely opening or publishing a document never runs a warehouse query.</p>
      <ul>
        <li>DuckDB-backed CSV, Parquet, JSON, table, ClickHouse, and Metabase inputs.</li>
        <li>Provenance-stamped result tables and source-aware chart definitions.</li>
        <li>Named external credential profiles; inline secrets are rejected.</li>
      </ul>
      <div class="org2-command" aria-label="Data notebook commands">
        <span>Inspect first; materialize only when you choose</span>
        <pre><code>org2 query-data --file notes/readiness.org2 --inspect
org2 query-data --file notes/readiness.org2 --results weekly --apply</code></pre>
      </div>
      <p class="org2-feature-links"><a href="language-reference.html#local-datasets-and-sql-views">Read the notebook syntax</a> <a href="tooling-reference.html">See query-data options</a></p>
    </div>

  <section class="org2-feature-story org2-feature-story-reverse" id="meetings-context" aria-labelledby="meetings-context-title">
    <div class="org2-feature-copy">
      <p class="org2-kicker">Meetings + context records</p>
      <h2 id="meetings-context-title">Turn a conversation into durable, connected work.</h2>
      <p>The macOS Workspace can record or import a meeting, keep audio and transcripts local, and render summaries, decisions, and follow-ups from ordinary files. Those records can then feed agenda items, cited agent runs, entity pages, and reports.</p>
      <ul>
        <li>Local-first transcription with explicit artifact paths and status.</li>
        <li>Event and timeline metadata for connecting meetings, people, projects, and later work.</li>
        <li>Raw evidence, curated notes, generated drafts, and published output retain provenance.</li>
      </ul>
