#+TITLE: OpenOrg and Org2
#+SUBTITLE: The product is OpenOrg. The open substrate is Org2.

* The boundary

OpenOrg is the native workspace, onboarding, integrations, and overall experience for running work with people and agents from local files you control.

Org2 is the open =.org2= format, compiler/runtime, CLI, npm package, schemas, and editor tooling underneath it. Org2 remains useful without OpenOrg, and OpenOrg does not replace the ordinary files with a private canonical database.

* What remains portable

- Ordinary =.org2= and =.org= files remain the source of truth.
- The =org2= CLI and =org2-lsp= keep their names and contracts.
- The npm package remains =@aviaviavi/org2=.
- VS Code, Vim, Neovim, Emacs, CLI JSON, and MCP clients can work with the same corpus.
- Agent runs, workflows, approvals, citations, and provenance remain inspectable corpus records.
- Any configured local, remote, hosted, or self-hosted agent can participate above the deterministic Org2 compiler.

* What OpenOrg adds

- A native Mac workspace for capture, Agenda, files, meetings, agents, and review.
- A five-minute first-run path from a folder to a cited agent result.
- Clear approval boundaries for consequential actions.
- Local configuration of agent destinations and explicitly authorized context.
- Packaging, updates, diagnostics, and a coherent product experience.

* Compatibility promise for the alpha rename

The display name changes without changing the existing macOS bundle identifier, preferences domain, Keychain service names, corpus format, CLI names, package names, or schema identities. Existing users should retain corpus access, settings, credentials, pairings, and permissions when moving from Org2 Workspace to OpenOrg.

See [[file:language-reference.org][Org2 language reference]] for the format and [[file:editors-macos.org][OpenOrg for macOS]] for the product client.
