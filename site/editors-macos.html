OpenOrg for macOS

A native workspace for local notes, planning, meetings, and agent work.

OpenOrg brings an ordinary folder of Org and Org2 files into one Mac app. Your files remain the source of truth, so you can also read, edit, sync, or version them with tools you already use.

Start with an agent and today's note

On first launch, OpenOrg creates a plain-text workspace automatically and asks you to connect an agent already available on your Mac. Choose local Codex, local Claude Code, or an OpenClaw Gateway you already run. You can also continue without AI; OpenOrg does not require an account or agent.

After setup, Home opens immediately with a chat box and today's daily note side by side. Ask a question, write in the note, or do both. New notes use .org; existing .org2 files remain fully supported and are not renamed. The initial workspace lives in a normal folder that you can move or rename. Use OpenOrg → Settings… → Workspace to update its portable name and kind, reveal it in Finder, or open a different corpus.

If you already keep notes in another folder, choose it from the workspace options during setup or mount it later from the corpus switcher. OpenOrg derives its views without moving your source of truth into a private database.

Global capture works anywhere on your Mac while OpenOrg is running. Press Cmd-Ctrl-Return to add a note or task to today's daily note, including dates, tags, links, files, or images.

OpenOrg stores daily notes in the corpus's daily/ zone by default. Set roam.dailiesDir in org2.json to a valid absolute path or a directory relative to the corpus root to use a different location; missing or invalid values fall back to daily/ rather than the corpus root. OpenOrg creates a missing daily note when you navigate to it by default. To let another job own creation, enable Disable automatic daily note creation in Settings → Workspace. Daily links then open existing files only and offer Create Daily Note when the target is missing.

The workspace

Agenda

see scheduled work and deadlines across one or all open corpora. Filter by date, assignee, status, priority, topic, or text; mark items done, reschedule them, change priority, or open the source note.

Files

expand the cached corpus file tree directly in the sidebar, or use the full tree and search surface for Org, Org2, Markdown, CSV, and generated workspace files.

Agent Work

follow delegated runs, inspect outputs and citations, and handle decisions that need you.

Meetings

record or import audio and keep transcripts, summaries, decisions, and follow-ups together.

Sources

connect supported external sources such as Slack and Notion, run a sync, or control its schedule.

Skills

inspect workspace-authored agent procedures, open their SKILL.md source, create a new skill, or move one to the Trash.

AI Chat

talk with any configured local, remote, hosted, or self-hosted destination using selected workspace context.

Search and Quick Open

find text, tasks, files, people, projects, meetings, agent work, and chat threads without remembering where they live.

You can open several corpora and switch between them from the sidebar. Agenda and Search can read across all mounted corpora, while writes stay scoped to the active corpus.

Use tabs to keep several documents or workspace views open without mixing their navigation history, selected surface, surface mode, row selection, or two-pane layout. An Agenda tab therefore returns to Agenda, while an Agent Work or Skills tab returns to its own view and selection. Press Cmd-T for a new tab and Cmd-Shift-[ or Cmd-Shift-] for the previous or next tab. Drag tabs to reorder them, or right-click one to duplicate, move, close, or close the other tabs.

Open Skills from the sidebar or press Cmd-Shift-K. Skills are ordinary SKILL.md files under .agents/skills/. Select a workspace-authored skill to edit it in the normal document pane, use New Skill for a safe starter file, and use the row menu to reveal it or move its whole folder to the Trash. Invalid skill files remain visible with a repair message instead of disappearing from the manager.

OpenOrg supplies its core Org2 operating guidance ambiently to every AI chat, so the reserved org2 infrastructure skill is not shown as a user workflow or slash command. Its corpus copy remains available to external skill-aware agents. The Skills surface is for additional procedures authored for this workspace.

Write and read

OpenOrg offers two views of the same document:

  • Read renders headings, links, properties, tables, citations, media, source blocks, and other Org structure.

  • Edit Source provides a native macOS text editor with syntax highlighting, folding, diagnostics, list continuation, TODO and planning commands, link insertion, undo, and safe saving.

An optional split view keeps source and rendered preview visible together. Rendered tables can be filtered, sorted, and resized without changing the source. CSV files open in an editable table with a raw-text fallback.

Large source blocks, including run machine-state JSON, start collapsed in the HTML reader and preview. Open the source disclosure to read or copy the complete block. Ordinary HTML exports remain expanded.

Trusted Org2 plugins can add renderers for source-block languages. The shared CLI HTML runtime powers both read mode and source preview, so the same plugin also works in org2 export html without a separate Mac extension or app rebuild. Renderer UI runs in a sandboxed, opaque-origin frame. See Tooling reference → Plugins.

OpenOrg can export an ordinary document or selected subtree as a clean PDF. Document PDFs preserve styled headings and content while omitting heading stars, outline guides and their indentation, disclosure arrows, property drawers, and interactive controls such as Ask AI. It can also preview slide decks and export presentation PDFs. Publication uses a disclosure-safe copy that removes private workspace metadata and unresolved local references from the shared output.

Discover connections

Open a note or stable-ID heading, show its Context pane, and choose Graph. Choose 1 hop for immediate incoming and outgoing links or 2 hops for neighbors of neighbors. Click a node to center its neighborhood; drag nodes to arrange the drawing. The arrows point toward linked targets. Search the visible node list and use Open source or a node’s arrow button to navigate to its exact source heading. Current note resets an explored neighborhood to the open document. Notes without IDs display an empty discovery state; add a #+ID: file keyword or an ID property in the heading’s drawer, then refresh.

Unlinked mentions lists exact title and alias occurrences in other files. Use the cited file and line to inspect the source, then click Link to replace that one occurrence with an explicit ID link. When a title or alias identifies several notes, Choose target lists each destination with its file and ID. This choice is always explicit. If the source or target changes before linking, refresh the panel and review the occurrence again. Finish an active source edit before linking into that file.

The panel scans only the active corpus and observes its ignorePatterns. Archives, hidden/build directories, sync conflicts, and symlinks are excluded. Neighborhoods are bounded to 60 nodes and mention results to 200 occurrences; a visible message identifies a truncated result. Refresh rescans source files. Existing links, quoted text, inline code/verbatim, URLs, indented fixed-width text, blocks, drawers, heading TODO/priority/tags, and generated Backlinks sections are protected by shared linkify rules. Heading titles remain linkable. Only actual note and heading IDs identify graph targets; IDs shown inside examples do not. Heading IDs remain available when planning lines precede their property drawer. Documents with invalid syntax are skipped until repaired. Broad semantic suggestions remain in the existing review-only linkify report. The graph and mentions are disposable projections; new links are ordinary source text and work in CLI, editors, and exports.

Spatial Canvas workspaces

Open Files → Canvas → New Canvas… and choose a .canvas file inside the active corpus. Existing Canvas files appear in Files and open directly as spatial boards. Import Canvas… copies a JSON Canvas document into the corpus; its original remains unchanged. The board uses the open JSON Canvas 1.0 format, so the file can move between compatible applications.

Use Add card for text, a note or stable-ID heading, an image or attachment already inside the corpus, a web link, or a group. Drag a card’s header to move it and its lower-right handle to resize it. Select a card and choose Edit to change text or a link, or Color to distinguish it. Markdown text is preserved in the file and displayed as text on the board. Imported node order is retained in the JSON file; groups are displayed behind connections and other cards. Moving a group moves its frame, not its contents.

Select a card, click Connect, then click the destination card. The board saves the connection immediately. The ellipsis menu lists connections; select one to edit its label, endpoint sides, arrow ends, and color, or delete it. Deleting a card also removes its incident connections. Pan by dragging empty space or enable the hand tool to pan across groups and cards, use zoom buttons to inspect details, and choose Fit to see the whole board.

Open source navigates notes and headings to the runtime-resolved source. When a note or heading has an ID, cards added through the note picker retain that stable Org2 reference, so a renamed source continues to resolve. Images are previewed locally; web links open only when clicked. Missing sources, ambiguous IDs, unsupported URL schemes, and unfamiliar node types stay visible as placeholders. Canvas never follows resource paths or symlinks outside the active corpus. The note picker excludes raw captures, hidden files, archives, and configured ignores. Only actual note and heading IDs resolve; IDs displayed inside source blocks or examples do not create targets. Planning lines before heading properties remain supported, and previews use the canonical note or subtree while omitting example blocks and metadata.

Each completed move, resize, or edit saves through the shared runtime with the file’s revision. A concurrent change is refused; reload the board before retrying. An editor that reports an error offers Reload board and keep draft, preserving your pending text and settings for review before saving again. Editor inputs stay locked while a save is pending. The ellipsis menu’s Export Canvas… writes an exact copy to a new file, including unknown fields. Import and export preserve the original JSON bytes; edits preserve unknown top-level, node, and edge fields while formatting JSON. Referenced attachments remain separate files and should travel with the corpus. Canvas files under raw/ or hidden runtime directories cannot be edited.

Publish a document

Open an Org or Org2 document, open its document menu, and choose Publish Document…. The same sheet also opens from /publish document in AI Chat. Choose the entire document or the subtree at the current reading/editing position, then inspect the disclosure preview before publishing.

The publish sheet separates the destination from the format:

  • Local Link can serve a read-only Web page, fixed-layout PDF, or compiled Beamer slides (PDF). Web pages use the same fluid, bounded document layout as OpenOrg's reader; long text wraps, charts shrink with the viewport, and wide tables scroll inside the page instead of widening it. The destination creates a high-entropy secret URL from the Mac and persists its sealed artifact locally. Publishing the same document or subtree and format again updates that URL in place, including links created before stable republishing was introduced. Devices must be able to reach the Mac on the local or private network. OpenOrg must be running for a link to be reachable, and active links resume at the same URL after OpenOrg relaunches. The initial server uses unencrypted HTTP, so use it only on a network you trust. Open Settings → Sharing to see every source file and format currently hosted, open or copy a link, stop one, or stop all of them.

  • Google Drive can create an editable Google Doc, Google Slides deck, or Google Sheets workbook, or upload a fixed-layout PDF. Slides use the selected content's slide headings. Sheets create one tab per Org table and refuse a selection with no tables. The optional folder ID selects a Drive folder; otherwise Google places the file in the connected account's default location. After the first successful publish, OpenOrg saves that format's Drive file ID, link, guarded version, and publish time in the selected document or subtree property drawer. The green Google Drive badge beside the document title reopens or copies saved artifacts, and publishing the same scope and format again updates the linked file instead of creating a duplicate. OAuth credentials remain in macOS Keychain and are never written into the source. Google Drive owns sharing and identity. Connect Google Drive opens Google's consent page in the default browser using the desktop loopback and PKCE flow, requests only the per-file drive.file scope, and keeps the refresh credential in macOS Keychain.

Web pages and fixed-layout PDFs embed deterministic chart and plot visualizations. A chart's source table must be inside the published document or selected subtree; publishing never follows a chart reference back into unselected corpus content.

Distributed OpenOrg builds include OpenOrg's registered Google OAuth client, so normal setup is one click on Connect Google Drive followed by consent in the system browser. Users do not create a Google Cloud project or import credentials. Use a custom OAuth client remains available as an advanced option for self-built or separately branded deployments; it accepts the JSON for a client of type Desktop app, not Web application. OpenOrg masks the paired client secret and stores it only with the resulting OAuth credential in macOS Keychain. Google passwords and OAuth tokens are never pasted into OpenOrg. See Google's desktop OAuth guide, Google's OAuth overview, and Drive scope guidance.

Property drawers, TODO state, tags, planning and clock data, comments, commented subtrees, dynamic blocks, table formulas, raw HTML, internal IDs, unresolved local links, and runtime data are removed before either destination receives content. Referenced supported raster images are embedded in the sealed artifact.

Agent work and approvals

Agent Work keeps each delegated job together with its goal, context, progress, outputs, citations, checks, and final outcome. The Runs view shows what is active, blocked, complete, or failed. The Review view collects the specific decisions that require a person.

You can approve, reject, request changes, discuss, or record that work was completed elsewhere. Batch selection applies independent decisions concurrently, coalesces the visible queue update and reconciliation, and still serializes writes that target the same canonical run or source file. Review material stays inspectable after a decision, providing a durable record of what was proposed and what happened.

The Automations view turns a prompt, optional agent profile, schedule, and any enabled AI destination into an ordinary file under workflows/. Its scheduler strip identifies the corpus-wide host responsible for scheduled runs and links to the same read-only ownership information in Workspace settings. OpenOrg checks schedules while it is running, creates a durable run before dispatch, catches up the latest missed occurrence after sleep or relaunch, prevents overlapping attempts, and keeps one destination-neutral history. The toolbar and row menu can delete a selected definition after confirmation without deleting its prior run history. Fuller reusable workflows use the same files and add inputs, steps, validation, outputs, and approval boundaries. See Automations and workflows for the full lifecycle.

AI chat and agents

AI is optional. OpenOrg does not require an OpenOrg account, and ordinary note, Agenda, search, meeting, and document features work without an AI destination.

In OpenOrg → Settings… → AI Chat, you can configure named destinations including local Codex, local Claude Code, remote Codex App Server, OpenClaw, OpenAI-compatible providers, Anthropic, OpenRouter, or Ollama. API keys are stored in macOS Keychain, not in the corpus.

The chat header’s AI Chat Settings… button opens this settings pane directly. The composer combines model and reasoning effort in one compact pill. Open it to choose a model, adjust supported effort levels with a stepped slider, or reset effort to its default. The destination remains alongside it; narrow panes collapse its label, and very narrow panes put the controls above the send actions. Shared rooms use a compact Models menu for their per-destination choices. To configure the built-in OpenClaw gateway, choose Edit beside its destination in Settings, then Configure Gateway…; gateway connection and pairing controls appear only in that editor. Brief and inactive-thread preferences live in the shared Conversations section.

Enable Experimental features in Settings → Workspace to reveal the opt-in Workspace tools (experimental) setting in each direct-provider destination under AI Chat. Experimental features are off by default and apply across workspaces on this Mac. Turning them off hides these controls, stops any active bundled agent turn, and returns subsequent turns to ordinary context-only chat; saved per-destination tool preferences are retained.

The bundled agent runs a small TypeScript executor using the Node runtime already shipped inside OpenOrg; no separate agent harness or Node installation is required. The executor can search the active corpus, read effective file text (including unsaved editor drafts), and propose whole-file edits. Every apply request opens a native review of the original and proposed text. Cancel declines edits for the rest of that turn. OpenOrg binds tools to the originating turn and authorized corpora, and rechecks the exact preview's hashes before writing.

This prototype supports text conversations with tool-capable OpenAI-compatible, Anthropic, OpenRouter, and Ollama models; support for an endpoint does not guarantee that every model can use tools reliably. Configure a model and endpoint in the destination, enable workspace tools, then try asking for a cited answer and a small task edit in a disposable corpus. Cloud credentials use the existing Keychain configuration. Local Ollama requires a separately running server and an installed model.

Only one bundled turn runs at a time. Replies arrive after each model step, with tool progress between steps; token streaming, automatic context compaction, restart recovery of an in-flight tool loop, attachments, general shell/browser access, and unattended edit approval are outside this prototype. Stop terminates the helper; the existing chat history and successfully applied file changes remain in OpenOrg. Each turn has a 12-step limit, a 48-tool-call limit, a 4 MiB context/response limit, and a two-minute timeout per model request. Workspace tools are disabled by default, preserving context-only chat for existing destinations.

To use Claude Code, install it and sign in with claude auth login, then enable Claude Code in AI Chat settings. OpenOrg starts the local CLI, streams its replies, and resumes the same Claude Code session on later turns. No Anthropic key is copied into OpenOrg. The Local Agent Permissions setting maps to Claude Code's Plan, Accept Edits, or Bypass Permissions mode.

Add files, headings, selected items, images, PDFs, audio, or other supported attachments as explicit context. Typing @ finds corpus files and destinations. Chat text has one selection region across the bounded visible transcript, so a drag can copy across paragraphs, bullets, and consecutive messages without mounting an unbounded history. Selection highlights update directly during dragging, using the displayed native glyph layout without rebuilding the transcript on each pointer movement, including inside agent rounds. Copy buttons on snippets and messages show a green check for two seconds after a successful copy, then return to the copy icon. Copying again restarts that confirmation. Copying a table, either by selecting its cells or using the message’s Copy button, supplies a styled HTML table for rich-text destinations such as email and an aligned Org table for plain-text editors. In a shared room, mention a destination by name or use @all; every reply remains attributed to the agent that produced it.

Pasting 8,000 characters or 100 lines into AI Chat creates a Pasted Text.txt attachment so you can keep typing smoothly. Click its chip to preview it, or use its remove button before sending. Shorter pastes remain inline. UTF-8 plain-text attachments are included in full as user text when sending or steering any AI runtime; the stored conversation retains the compact attachment.

Agents can display images directly in their replies with an Org image link on its own line, such as [[file:/absolute/path/qr.png][QR code]] or [[https://example.com/chart.png][Chart]]. Image-only replies and images alongside prose both render inline, including in agent rounds. Relative paths resolve against the active local corpus. Local files must be accessible on the Mac; files generated on an SSH host must first be retrieved or synchronized to a local path. OpenOrg includes this guidance in the agent’s context. Tool output and opening another application do not by themselves attach an image to the conversation.

Pass to Agent menus list active portable agent profiles from the corpus. Choosing one writes its readable name as ASSIGNEE and preserves its stable AGENT_REF plus primary GOAL_REF when available; the configured legacy handoff target remains available as a fallback.

Threads and their context are stored locally with the corpus. Right-click a sidebar thread and choose Copy Thread ID to copy its stable OpenOrg UUID, usable with Org2 thread commands; this is independent of the runtime’s session ID. Hover or select a sidebar thread to reveal its Settle action; settled threads show Reopen instead. The selected thread keeps its action visible even when the pointer moves away. The action keeps its space in narrow sidebars so hovering does not shift the title. Long-running OpenClaw turns can stream progress, be stopped, and reconnect after an app restart when the connected runtime supports it.

If chat history cannot be loaded safely, OpenOrg pauses transcript writes and shows a recovery notice with a Retry button. Retry after synchronization finishes or missing files are restored. Recovery can reconcile verified thread history from incomplete or divergent synced commits; recent unreferenced thread and attachment files receive a 30-day grace period before cleanup.

The iOS app can relay Codex, Claude Code, and other configured chat destinations to a paired Mac over Tailscale. The selected host remains responsible for corpus access and model connections. A headless OpenOrg server on another Mac can keep chats and scheduled automations available while the laptop is away. See iOS setup for the current beta and pairing path.

See Agent quickstart for permissions, runtime integration, durable runs, and automation details.

Meetings and external sources

Meetings can be recorded in OpenOrg or created from an existing audio file. Choose local Whisper, macOS Speech, Fluid Voice, or a custom local command for transcription. The resulting audio, transcript, metadata, and notes remain visible in the corpus. A freshly transcribed meeting can optionally be sent to a named AI destination for a summary or follow-up workflow.

The Sources view manages supported Slack and Notion connections. Each connector can run on demand, pause or resume its schedule, and use a repeating interval or daily time. Imported material is staged for review rather than silently promoted into your canonical notes, and credentials remain outside the corpus.

Saved property views

Choose Saved Views in the workspace sidebar to open live tables and cards made from the active corpus. The landing page explains the feature without scanning the corpus. Describe a result in plain language, such as “Show my unfinished project tasks grouped by project,” or choose an example; OpenOrg turns that request into a visible draft and queries only its selected folder. Review the matching rows before saving. Existing views appear immediately and run only when selected.

Use Edit View for the advanced builder. Choose Headings, Notes, or Both, optionally narrow the corpus-relative folder prefix, and list columns separated by commas. Built-in columns are title, document, file, kind, todo, tags and id; other names select case-insensitive property keys. Use Add Filter for equality, containment, presence, numeric conditions, or active/terminal TODO state; choose all/any matching, sort fields, and an optional grouping field. Apply View previews the new result before Save View persists it. New and Duplicate create separate definitions. Refresh reloads a saved definition and its current source rows.

Click a property cell in either layout, edit the value, choose Preview Change, then Apply to Source. The preview shows the old local value and proposed value. An arrow marks inherited properties; editing them creates an override on the selected note or heading. Empty text creates an explicit empty value. Source links open the exact file and line. Save or cancel an open source editor before making cell edits. A stale source or saved definition fails with a refresh message instead of overwriting newer work. Built-in fields, stable IDs, ORG2_ runtime metadata and immutable raw/ imports remain read-only here.

Definitions are ordinary views/ID.org2-view.json files using org2:property-view:v1. Copy one into another corpus's views/ directory, keeping its filename matched to its ID, to reuse it there. Views contain relative scope and presentation/query choices, with no private database or machine paths. Rows are derived on Apply/Refresh and after a successful edit; a saved view never copies note bodies. The default builder shows at most 500 rows and indicates truncation. The CLI supports limits up to 5,000 and multiple sort fields. See Tooling reference for the portable schema and automation commands.

Data notebooks and charts

Org2 documents can connect notes to CSV, Parquet, JSON, ClickHouse, or Metabase data, define SQL views, materialize results, and render charts. Refresh is explicit: opening a note never runs a remote query. Results retain source and freshness information so readers can see where the numbers came from.

Privacy and security

Your corpus is an ordinary folder on your Mac. OpenOrg does not upload it to an OpenOrg service. Information leaves the Mac only when you use a destination or source provider you configured, so its retention and data-use policy still applies.

Secrets belong in macOS Keychain or another protected local store. OpenOrg also supports GPG-backed :crypt: subtrees when individual sections need encrypted storage. Consequential external actions can be held for explicit approval before execution.

Back up or sync the corpus with a file-oriented tool you understand, such as Git, Time Machine, iCloud Drive, or Syncthing.

Keyboard essentials

  • Cmd-1 through Cmd-6 open the main workspace surfaces.

  • Cmd-P opens Quick Open. Cmd-K also opens Quick Open outside the Source editor; inside it, Cmd-K inserts a link.

  • Cmd-Ctrl-Return opens global capture.

  • Cmd-7, Cmd-8, and Cmd-9 open today's, yesterday's, and tomorrow's daily notes in the document pane. The Daily sidebar links and Choose Date… (Cmd-Shift-7) use the same behavior: they preserve the current first pane, including the selected AI chat and its draft, and do not open the Files list. If the document pane is closed, it reopens; an already closed first pane stays closed. With automatic daily note creation disabled for the workspace, a missing target shows an explicit creation button instead of writing a file.

  • Cmd-A selects visible items in Agenda, Files, Runs, or Review; Shift-Up/Down extends the selection.

  • Cmd-F searches the active pane.

  • Cmd-R refreshes the workspace when you need a manual reconciliation. Full refreshes of large corpora may take longer than 15 seconds; OpenOrg lets them continue without reporting a timeout error. Press Cmd-R again or click the stop control to cancel. Actual refresh errors are still reported.

  • Cmd-T opens a tab; Cmd-Shift-[ and Cmd-Shift-] move between tabs.

  • In AI Chat, Return sends or queues while a turn runs; Shift-Return inserts a newline. Cmd-Return (also Cmd-Shift-Return) steers a running turn, or sends normally when idle. When suggestions are visible, Up/Down selects and Tab or Return accepts a suggestion.

  • Cmd-N creates an AI thread.

  • In Agenda, w schedules next Monday and m schedules the first of next month; uppercase W and M set the corresponding deadline.

Use Help → Keyboard Shortcuts… (Cmd-/) for the full reference, including the Source editor commands. Shortcuts depend on the focused pane or editor; bare uppercase letters (such as J) in the reference mean Shift.

Full refresh updates the selected document first, then runs up to two independent refresh jobs concurrently. File catalog and assigned-work refreshes stay ordered. Agent-state lists share one CLI request; native assigned-work and similar-TODO scans reuse unchanged file fragments and invalidate them on edits, replacements, or deletions. Timing records for each awaited refresh stage are available through the diagnostics log.

Large file-sync batches preserve every changed path when updating the search index. Oversized CLI argument lists travel through a private temporary file, removed after the request, so macOS process argument limits do not crash the workspace.

Install and troubleshoot

Download the signed and notarized app from Downloads. Developers who want to build OpenOrg from source can follow the repository instructions on GitHub.

OpenOrg checks for signed updates when it opens and every two hours by default. Use OpenOrg → Check for Updates… to check manually, or the Updates settings to turn automatic checks off and choose whether downloads should install when you quit. Update prompts can also remind you later or skip a version.

Quitting during active chats, recording, or meeting processing asks for confirmation. OpenOrg makes a best-effort save for up to five seconds after you confirm. A second Quit request (including Cmd-Q or AppleScript) bypasses the pending confirmation or save and exits immediately; unsaved changes or recent output may be lost. If an ordinary quit cannot finish saving, a visible dialog offers Quit or Keep Open; slow saves offer Quit or Keep Waiting. Developer --restart builds send a second quit request after five seconds if needed, and only replace the bundle after the app exits.

For a reproducible launch or refresh problem, use the macOS diagnostics guide. Sanitize diagnostics before sharing them, and never include credentials or private corpus content.

Custom TODO states and action feedback

Open Settings → Workspace → TODO States to edit corpus-wide defaults. Enter space-separated names in the Active states and Terminal states fields. Add independent sequences as needed, then choose Save TODO States. Use Built-in States clears the custom rows; Save applies that choice. Validation errors stay beside the fields, and stale settings require a reload before saving. The settings are portable corpus configuration, shared by the CLI and other clients.

A file can override these defaults. Add a declaration such as #+TODO: TODO MISSED | DONE SKIPPED to a file. States before | remain active; those after it are terminal. OpenOrg’s heading editor includes the declared keywords, and heading buttons use the configured active/terminal states. Marking a custom state DONE replaces its keyword, preserves the title and ID, and maintains CLOSED metadata.

Workspace errors appear in a dismissible banner on the current surface, with selectable details. Failed actions no longer depend on a hidden status message; successful actions do not open confirmation dialogs.

Experimental Paste as Org2

Enable Experimental features in Settings → Workspace. In a document's Source editor (including split view), place the caret or select text, then choose Edit → Paste as Org2… (⌘⇧V). Review or edit the Org preview, then choose Insert reviewed Org. Cancel leaves the document unchanged; insertion uses normal editor undo and save behavior. Ordinary paste is unchanged.

Conversion runs locally and only when invoked. Semantic clipboard HTML takes precedence; plain text uses conservative heuristics, with an optional tiny local structure model in the preview. The model is experimental and may mislabel structure. Words and quantities are retained; layout may flatten and uncertain material stays literal. Clipboard content is limited to 200,000 characters per format. No clipboard content is sent to an AI provider. Disabling Experimental features hides the command and prevents insertion from an open preview. The command is currently limited to the Source editor, not rendered inline editors, chat, or code-block bodies.

Projects

Choose New Project in the sidebar and give it a name. Color is optional and new projects start without one. Choose a quick swatch or use the full macOS color picker, and choose No color to clear an existing color. Optional project details become the starting brief, with no empty sections or placeholder tasks. The AI refinement option opens a linked chat with your selected destination to shape those details into a concise brief using the normal reviewed editing tools. Projects expand in the sidebar to show their linked chats without filtering the main AI chat list. The document button opens the project note; the plus button creates a linked chat. The action summary includes TODOs in the note and tasks linked elsewhere. Use a chat's Projects menu to add or remove membership. A chat can belong to several projects. Right-click a project and choose Choose color to use the full picker, or select a quick color. Refresh projects reloads note edits.

Only explicit chat membership supplies project context; expanding a sidebar project does not change another chat's prompt. Linked chats receive a bounded note excerpt with source path and revision, refreshed with the corpus. At most eight notes and 12,000 brief characters are included per turn. Project membership does not import other conversations or change corpus permissions. Save an open project-note draft before changing its color or chat membership.

Interaction feedback

Action buttons use a brief native press response. Settling or reopening a chat animates its sidebar update; approval cards fade as resolved items leave the review queue or run detail. These effects respect the macOS Reduce Motion setting and do not delay actions.

Chat text selection

The visible chat transcript is one document with one WebKit scroll surface, using the same Org HTML renderer as document previews. Drag to select across messages, paragraphs, lists, tables, and code; standard Copy preserves rich text. Incoming document updates wait while a text selection is active. Message boxes do not scroll independently. Icon copy buttons preserve complete message or code source. Context, attachments, failures, queued-message actions, reasoning and tool activity, and file-change summaries remain inline with their messages. Earlier-message paging, thread search, saved scroll position, and jump-to-latest remain available. Agents are instructed to output Org syntax throughout, including citations such as [[file:notes/example.org::42][source]]. Older Markdown-style chat citations remain supported.

Project navigation and chat agents

Project header icons create a project or reload its notes. Colored projects add a subtle marker beside member threads in the main chat list; uncolored projects do not tint their threads. Hover over a marker to see its project names.

The composer shows agent and runtime as separate controls. Choosing an agent stores the profile's stable ID on the thread and supplies its role, responsibilities, skills, and goal context on subsequent turns. On an empty thread, a profile with a default runtime adopts that runtime as its starting choice; the adjacent runtime control remains visible and can override it. An agent can change between turns, while the runtime remains fixed once a conversation starts. Choosing Default assistant removes the explicit profile. Profile selection does not import other chats or grant additional corpus access.

Live note and heading embeds

Use the document File → Live Embed… menu, or Insert → Live Embed… in the source editor. Search the note list or enter id:STABLE-ID for a note or heading. Insert Embed validates the target through the shared runtime, opens the split editor, and inserts a portable #+EMBED: reference into your draft. Save with the normal editor controls.

#+EMBED: file:../notes/project.org
#+EMBED: id:project-decisions

A file target includes the whole note. An ID target includes the file or heading subtree identified by its :ID: property. Relative file paths resolve from the referencing note; nested references and images resolve from their own source files. The source remains canonical, and corpus file changes refresh the selected rendered document and split preview. Each embed has Open source navigation and a scrollable, read-only content frame; edit the original source to change its content. Embedded headings and tables do not acquire controls that could mutate the host note.

Missing or duplicate IDs, cycles, and limits appear inline. Resolution stays within the active corpus, including after symlink resolution. Nesting stops after four levels, with at most 32 references and 1 MiB of total embedded content per render; a single embed is limited to 256 KiB. ID lookup scans at most 10,000 notes / 64 MiB, honors corpus ignore patterns, and excludes files larger than 4 MiB. For a large source, embed a smaller stable-ID heading or use a normal link.

Exports do not fetch embedded source content. Ordinary HTML exports keep a textual source reference; Export Current Document as PDF keeps the source reference without its live frame. Publish Document replaces embeds with a target-free omission marker in every destination, including web, PDF, and Google Workspace exports. Publish the referenced source separately to review its disclosure. Source .org / .org2 files preserve the portable directive.

Browser article and selection clipping

Install the source-distributed Chromium extension from this repository's integrations/browser-clip/ directory: open chrome://extensions (or edge://extensions), enable Developer mode, choose Load unpacked, and select that directory. Pin OpenOrg Web Clipper. There is no store installation or background network service. The extension uses temporary access to the tab you explicitly invoke it on.

  1. Open an HTTP(S) article. Optionally select a passage before clicking the clipper.

  2. Choose Article or Selection, review the extracted text, title and available author, and choose Reading note or Read later task.

  3. Click Save clip and save the portable .org2clip file.

  4. In OpenOrg, open Capture and choose Import Browser Clip. Choose the file, review its text and metadata, adjust the template if needed, then click Import.

  5. The imported note opens in views/browser-clips.org. Its source URL, author, capture time and hash are in the property drawer; the complete capture envelope is retained under raw/browser/. If you already had an unfinished Capture draft, that window stays open with your text, attachments and settings intact; finish or cancel it to see the imported note underneath.

Article capture prefers a visible article, then visible main, then page text, removing navigation, forms, scripts and content hidden by page CSS or visibility attributes. The preview identifies page-text fallback. It captures currently loaded text, not images, paywall bypasses, PDF viewers or browser-internal pages. Selection capture keeps the selected plain text, trimming surrounding whitespace and normalizing line endings on import; article extraction preserves paragraph boundaries. Content is stored as literal text so source directives cannot execute as Org instructions. Review and promote useful material into canonical notes as an explicit separate action. Duplicate imports of the same clip/template do not append another copy, including after CRLF or drawer formatting changes. Only real heading provenance counts as an import receipt; quoted examples do not suppress capture. A changed source clip or destination requires another preview.

Cancel is unavailable while an import commits. Closing the sheet or changing the corpus or Capture window invalidates pending UI work, so an old operation cannot navigate away from a newer draft. If a source edit starts while import finishes, the clip stays saved without changing the editor; open it from Files after finishing that edit.
